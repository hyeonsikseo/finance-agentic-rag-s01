# 문제 정의서 — 한빛저축은행 상담사 약관 조회 보조 (예시)

> 강사가 인터뷰 시연 내용으로 채운 예시입니다. 실제 프로젝트에서는 첫 주가 끝날 때 이 문서가 나와야 합니다.
> 앞부분은 우리끼리 보는 디스커버리 노트이고, 뒷부분은 고객에게 보내는 SOW-lite 한 장입니다.
> 수업 코퍼스 51건을 한빛저축은행의 문서로 간주합니다.

작성 2026-09 | 고객사 한빛저축은행(가상) | 작성자 강사

## 1. 이해관계자

| 역할 | 누구 | 이 사람이 원하는 것 | 이 사람이 무서워하는 것 | 결정권 |
|---|---|---|---|---|
| 현업 | CX팀장 김○○ | 상담사가 고객을 기다리게 하지 않고 답하는 것. "다시 연락" 절반으로 | 재작년 챗봇처럼 자신 있게 틀리는 것. "모르겠다"가 잦아 아무도 안 쓰는 것 | 중 |
| 보안·규제 | 정보보호팀장 이○○ | 개인신용정보가 밖으로 안 나가는 것. 감사에 답할 수 있는 로그 | 질문에 섞인 고객 이름이 외부 API 로 나가는 것. 로그에 고객 정보가 남는 것 | 상 (위원회 상정 권한) |
| IT 운영 | IT운영팀장 최○○ | 운영 부담이 적은 컨테이너 배포 | GPU 품의 6개월, 반입 창구 분기 1회를 무시한 일정 | 중 |
| 예산 승인 | 임원 (박 과장이 보고) | 다음 달 중순 보고에서 볼 것이 있는 것 | 돈을 썼는데 못 쓰는 것 | 상 |

**한 명이라도 반대하면 멈추는 사람**: 정보보호팀장. 위원회에 올리는 사람이 이분이라, 이분이 안 올리면 시작이 안 됩니다.

## 2. 현재 워크플로우와 소요시간

| # | 지금 하는 일 | 누가 | 걸리는 시간 | 하루 몇 건 |
|---|---|---|---|---|
| 1 | 고객 문의를 받고, 약관이나 상품 조건 확인이 필요한 문의를 가려낸다 | 상담사 42명 (신입 11명) | 즉시 | 1,200콜 중 180~240건 |
| 2 | 사내 포털에서 PDF 를 열어 Ctrl+F 로 조항을 찾는다 | 상담사 | 2~3분, 신입은 5분 이상 | 180~240건 |
| 3 | 못 찾으면 "확인 후 다시 연락드리겠다"로 끊고 나중에 회신한다 | 상담사 | 통화 한 건이 더 생긴다 | 30~40건 |

**가장 오래 걸리는 단계**: 2번 조항 찾기.
**그 단계가 오래 걸리는 진짜 이유**: 검색이 느려서가 아닙니다. 같은 약관이 판본이 여러 개인데 포털에는 최신본만 있고, 고객이 가입한 시점의 판본이 어디 있는지 아무도 모르기 때문입니다.

## 3. 성공 지표

고객의 말로 한 줄:

> "확인 후 다시 연락드리겠다가 하루 30~40건인데, 그게 절반으로 줄면 성공이라고 봅니다." (CX팀장)

| 지표 | 지금 | 목표 | 어떻게 잴 것인가 |
|---|---|---|---|
| 조항 찾는 시간 | 2~3분 | 30초 안 | 상담 로그의 조회 시작~답변 시각 |
| "다시 연락" 건수 | 하루 30~40건 | 15~20건 | 콜센터 일일 집계 |
| 검색 정확도 Recall@5 | 모름 | 기준선을 잰 뒤 정한다 (3회차) | 골든셋 60문항 |
| 답변 근거 정확도 | 모름 | 기준선을 잰 뒤 정한다 | 수동 라벨 20문항 |
| 오거절률 | 없음 | 5% 이하 (초안) | 답할 근거가 있는데 거절한 비율 |

**목표 수치 한 줄**: "다시 연락" 하루 30~40건을 15~20건으로 줄인다. 그러려면 Recall@5 를 기준선보다 올리되, 오거절률은 5% 이하로 유지한다.

## 4. 데이터와 망 제약

| 질문 | 답 |
|---|---|
| 문서는 어디에 있나 | 공유 드라이브, 부서별 폴더. 갱신 담당자가 없어 옛 파일과 중복이 섞여 있다 |
| 몇 건인가, 얼마나 자주 바뀌나 | 세어 본 적 없음(수천 개 추정). 상품이 나올 때 그 부서가 올린다 |
| 개인정보가 섞여 있나 | 문서에는 없음. 상담 이력과 상담사가 치는 질문에 고객명·계좌번호가 들어온다 |
| 인터넷이 되는 망인가 | 준-폐쇄. 업무망은 외부 통신이 원칙적으로 막혀 있고, 조건부 예외 경로가 있다 |
| 외부로 나가도 되는 것 | 개인신용정보가 없는 질문과 검색된 조항 본문. 위원회 승인 조건 |
| 외부로 절대 못 나가는 것 | 고객명, 계좌번호, 상담 이력 |
| 클라우드 사용 가능한가 | 불가. 평가받은 SaaS 예외는 별도 절차 |
| GPU 가 있나 | 없음. 품의 올리면 6개월. VM 16GB 두 대는 바로 가능 |

**준-폐쇄망 판단**: 외부 LLM API **조건부 가능**. 조건은 개인신용정보 미포함, 상담사 보조(대고객 아님), 위원회 보고와 반기 이행평가.

## 6. 리스크

| 리스크 | 일어나면 | 확률 | 지금 할 수 있는 것 |
|---|---|---|---|
| 틀린 답을 근거처럼 말한다 | 상담사가 그대로 읽어 민원. 재작년 챗봇 사고가 되풀이된다 | 상 | 근거 없으면 거절. 문서·조항·쪽 표기. 계산은 함수가 한다 |
| 만료된 판본을 근거로 답한다 | 옛 약관으로 답해 고객이 불이익을 본다 | 상 | 시행일과 심의 유효기간을 메타데이터로. 만료본은 경고 문구 |
| 문서 형식이 파서를 뚫는다 | 문서가 소리 없이 빠져 "근거 없음"이 된다 | 중 | 문서마다 파서를 고른다. 측정표로 미리 점검한다 |
| 반입 일정이 PoC 를 막는다 | 폐쇄망 전환이 다음 분기로 밀린다 | 상 | PoC 는 외부 API 조건부 경로로. 반입 신청은 지금 넣는다 |
| "모른다"가 너무 잦다 | 상담사가 PDF 로 돌아가고 시스템은 안 쓰인다 | 중 | 오거절률을 지표로 잰다 |

**"틀린 답을 하면 누가 책임지나요?"에 대한 답**:

> 시스템은 조항을 찾아 보여 주고, 답은 상담사가 근거를 확인한 뒤 합니다. 근거가 없으면 시스템은 답하지 않습니다. 모든 답에 AI 생성 표시와 "실제 계약은 약관과 증서가 우선합니다"가 붙습니다. 책임 구조는 지금 상담 프로세스와 같고, 시스템은 찾는 시간을 줄이는 보조 도구입니다.

# SOW-lite (고객에게 보내는 1쪽)

**과제** 콜센터 상담사가 약관과 상품설명서에서 해당 조항을 찾아 답하는 시간을 줄이고, 잘못된 판본으로 답하는 일을 없앱니다.

**지금 이렇게 하고 있습니다** 상담사가 사내 포털에서 PDF 를 열어 직접 찾습니다. (2~3분 × 하루 180~240건). 못 찾으면 "확인 후 다시 연락"으로 끊습니다 (하루 30~40건).

**이렇게 바꾸겠습니다** 상담사가 질문을 치면 시스템이 해당 조항을 판본 정보와 함께 찾아 보여 줍니다. 근거가 없으면 답하지 않고, 계산은 정해진 함수가 합니다. 상담사는 근거를 확인하고 답합니다.

**PoC 범위** 문서 51건 · 질문 유형 8종 · 4주

**성공 기준** "확인 후 다시 연락" 하루 30~40건을 15~20건으로. 오거절률 5% 이하.

**하지 않습니다** 고객 직접 응대, 개인신용정보 처리, 상품 권유, 문서 자동 수집.

**전제** (틀리면 계획이 바뀝니다)

1. 외부 LLM API 는 개인신용정보 미포함·상담사 보조 조건으로 위원회 승인을 받습니다.
2. PoC 는 정리된 문서 묶음으로 하고, 문서 갱신 정책은 PoC 이후에 정합니다.
3. 완전 폐쇄망 전환은 다음 분기 반입 창구를 씁니다. 반입 신청은 지금 넣습니다.

**필요한 것** (고객이 준비할 것)

| 무엇 | 언제까지 | 누가 |
|---|---|---|
| 약관·상품설명서 폴더 지정 | 1주 안 | IT운영팀 |
| 위원회 상정 일정 확인 | 2주 안 | 정보보호팀 |
| 상담 로그 표본 (고객 정보 제거본) | 1주 안 | CX팀 |
| 내부망 VM 2대 | 1주 안 | IT운영팀 |
